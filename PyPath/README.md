# PyPath — Base Version (v0.1.0)

A beginner-focused Python learning app for Android. Native Kotlin + Jetpack Compose (Material 3).

This is the **foundation build**: onboarding → dashboard → levels → sub-levels → lesson → MCQs → completion, with progress saved on the device. There are no ads, subscriptions, payments, XP, badges or code execution yet.

## Build

Requirements: JDK 17 and the Android SDK (platform 35).

```bash
./gradlew assembleDebug            # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease          # minified; signed with the debug key for testing only
./gradlew testDebugUnitTest        # progression, content and MCQ engine tests
./gradlew recordPaparazziDebug     # renders screen snapshots to app/src/test/snapshots
```

Min SDK 26 (Android 8.0), target SDK 35.

## Architecture

```
app/src/main/
├─ assets/course/course.json        ← all course content (generated by content/build_course.py)
└─ java/com/pypath/app/
   ├─ PyPathApp.kt                  AppContainer (manual DI: swap repositories here)
   ├─ MainActivity.kt               splash (held until progress loads) + edge-to-edge
   ├─ data/
   │  ├─ model/CourseModels.kt      Course → Level → SubLevel → steps, Lesson pages/blocks, Quiz/Question
   │  ├─ content/CourseRepository   interface + asset JSON implementation + CourseParser
   │  └─ progress/                  UserProgress model + DataStore-backed ProgressRepository
   ├─ domain/Progression.kt         CourseSnapshot: the only place that decides lock/unlock/current
   └─ ui/
      ├─ theme/                     colours (light/dark), Plus Jakarta Sans + JetBrains Mono, shapes
      ├─ components/                buttons, cards, pills, progress bar/ring, status node, CodeBlock, Python highlighter
      ├─ mcq/                       reusable MCQ engine (McqSession) + question/option/feedback UI
      ├─ navigation/NavGraph.kt     all routes
      └─ screens/                   onboarding, dashboard, level, sublevel, lesson, quiz, completion
```

### Key rules
- Content is **data**, not code. Adding a level or sub-level = edit `content/build_course.py`, run it, rebuild. No Kotlin changes.
- A sub-level is complete only when **every step in `steps`** is done. Today that's `learn` + `quiz`. The quiz step counts only when the learner reaches the `passPercent` (default 60%).
- Sub-levels unlock in order across the whole course. Levels with `"available": false` show as "Coming soon".
- Progress is stored as versioned JSON in DataStore: onboarding flag, current sub-level, completed steps, completion time, last/best MCQ score, attempts.

## Where future features plug in

| Feature | Hook |
|---|---|
| Practice / code editor | `StepType.PRACTICE` exists; add `practice` to a sub-level's `steps`, add a route + screen, mark `isSupported` |
| Level-final projects / assessments | `Level.finalAssessment`; gate in `CourseSnapshot`; `McqSession` can be reused for assessments |
| Recall system | `SubLevelProgress.completedAt` / quiz history; `McqSession` takes any question list |
| XP, badges, animations | derive from `UserProgress`; add fields with defaults (schema stays backward compatible) |
| Remote content / cloud sync | new `CourseRepository` / `ProgressRepository` implementation in `AppContainer` |
| Premium, rewarded ads | not implemented; would sit in a separate module behind `AppContainer` |

Settings menu (⋮ on the dashboard) has **Reset progress** for testing.
