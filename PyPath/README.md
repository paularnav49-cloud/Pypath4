# PyPath — v0.2.0 (Practical tab)

A beginner-focused Python learning app for Android. Native Kotlin + Jetpack Compose (Material 3).

Onboarding → dashboard → levels → sub-levels → lesson → MCQs → completion, with progress saved on the device, plus a **Practical** tab where learners write and run real Python on the phone. There are no ads, subscriptions, payments, XP or badges yet.

## Build

Requirements: JDK 17 and the Android SDK (platform 35).

```bash
./gradlew assembleDebug            # app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease          # minified; signed with the debug key for testing only
./gradlew testDebugUnitTest        # progression, content and MCQ engine tests
./gradlew recordPaparazziDebug     # renders screen snapshots to app/src/test/snapshots
./gradlew connectedDebugAndroidTest # on a device/emulator: real Python execution + Practical UI tests
```

Min SDK 26 (Android 8.0), target SDK 35.

## Architecture

```
app/src/main/
├─ assets/course/course.json        ← all course content (generated by content/build_course.py)
└─ java/com/pypath/app/
   ├─ PyPathApp.kt                  AppContainer (manual DI: swap repositories here)
   ├─ MainActivity.kt               splash (held until progress loads) + edge-to-edge
   ├─ data/
   │  ├─ model/CourseModels.kt      Course → Level → SubLevel → steps, Lesson pages/blocks, Quiz/Question
   │  ├─ content/CourseRepository   interface + asset JSON implementation + CourseParser
   │  └─ progress/                  UserProgress model + DataStore-backed ProgressRepository
   ├─ domain/Progression.kt         CourseSnapshot: the only place that decides lock/unlock/current
   └─ ui/
      ├─ theme/                     colours (light/dark), Plus Jakarta Sans + JetBrains Mono, shapes
      ├─ components/                buttons, cards, pills, progress bar/ring, status node, CodeBlock, Python highlighter
      ├─ mcq/                       reusable MCQ engine (McqSession) + question/option/feedback UI
      ├─ navigation/NavGraph.kt     all routes
      └─ screens/                   onboarding, dashboard, level, sublevel, lesson, quiz, completion
```

### Key rules
- Content is **data**, not code. Adding a level or sub-level = edit `content/build_course.py`, run it, rebuild. No Kotlin changes.
- A sub-level is complete only when **every step in `steps`** is done. Today that's `learn` + `quiz`. The quiz step counts only when the learner reaches the `passPercent` (default 60%).
- Sub-levels unlock in order across the whole course. Levels with `"available": false` show as "Coming soon".
- Progress is stored as versioned JSON in DataStore: onboarding flag, current sub-level, completed steps, completion time, last/best MCQ score, attempts.

## Where future features plug in

| Feature | Hook |
|---|---|
| Level-final projects / assessments | `Level.finalAssessment`; gate in `CourseSnapshot`; `McqSession` can be reused for assessments |
| Recall system | `SubLevelProgress.completedAt` / quiz history; `McqSession` takes any question list |
| XP, badges, animations | derive from `UserProgress`; add fields with defaults (schema stays backward compatible) |
| Remote content / cloud sync | new `CourseRepository` / `ProgressRepository` implementation in `AppContainer` |
| Premium, rewarded ads | not implemented; would sit in a separate module behind `AppContainer` |

Settings menu (⋮ on the dashboard) has **Reset progress** for testing.

## Practical tab (real Python)

The bottom navigation has two tabs: **Learn** (the existing dashboard) and **Practical**.

- **Runtime**: [Chaquopy](https://chaquo.com/chaquopy/) 17 (open source, MIT) bundles CPython **3.11** in the APK, for `arm64-v8a`, `armeabi-v7a`, `x86_64` and `x86`. Everything runs on the device - no server, no AI, no network. (3.11 is the newest Chaquopy Python that still ships 32-bit ABIs.)
- **Process isolation**: learner code runs in `PythonRunnerService` in its own process (`:python`). The UI process never runs Python, so `while True: pass` cannot freeze the app. **Stop** and the **10 s execution limit** (time spent waiting for `input()` is not counted) kill that process; a fresh interpreter starts automatically. Crashes or out-of-memory errors only take down that process.
- **I/O**: `app/src/main/python/pypath_runner.py` executes the code with `exec()` in a fresh `__main__` namespace. stdout/stderr and `input()` requests go to the service over OS pipes and are streamed to the console. `input()` shows an input field inside the console; the answer is written back to the waiting program.
- **Errors**: real CPython tracebacks (runner frames removed) are shown in the console; the error card shows the exception and a "Go to line N" shortcut parsed from the traceback.
- **Sandbox (best effort)**: the app requests no `INTERNET` permission. A permanent PEP 578 audit hook blocks sockets, subprocess/exec/fork/kill, ctypes, thread creation and any file access outside a per-run scratch directory (wiped after each run) and the read-only standard library - learner code cannot read app data such as saved progress. The Java bridge modules are hidden and `java`, `android`, `socket`, `subprocess`, `ctypes`, `urllib`, `http`, ... cannot be imported. A Python-level sandbox is not a hard security boundary against a determined attacker; the OS-level protections (separate process, no network permission, no credentials stored by the app) are the real boundary.
- **No permanent storage**: code is kept in memory (`PracticalViewModel`) for the session only. It is never written to disk, uploaded or synced.
- **Editor**: `CodeEditor` is a real `BasicTextField` (cursor, selection, copy/paste, hardware keyboards) with syntax highlighting, line numbers, auto-indent after `:`, Tab/Shift+Tab, and a shortcut key bar (Tab, unindent, brackets, quotes, operators).
- **Tasks**: `app/src/main/assets/practical/tasks.json`. Each task names `afterSubLevel` - the sub-level that teaches its last required concept - and unlocks only when that sub-level is completed. Tasks for unreleased levels (loops, lists) show "Coming soon". The Free playground is always open. The sub-level screen links its Practice step to its task.

Files: `practical/` (runner service, client, protocol, task catalog), `ui/screens/practical/` (screen, editor, view model), `ui/navigation/BottomTabs.kt`, `src/main/python/pypath_runner.py`, `src/androidTest/` (on-device tests).
